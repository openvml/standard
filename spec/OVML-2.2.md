# OpenVML — OVML 2.2 Specification

**Version:** 2.2  
**Status:** Current  
**Format:** XML  
**Specification:** OpenVML Standard

---

## 1. Introduction

OVML (Open Visual Media Language) is a declarative XML-based
standard for describing structured audiovisual content.

OVML is designed to describe not only media files, but the
relationships between:

- narrative content;
- characters;
- voices;
- scenes;
- camera direction;
- media assets;
- timing;
- subtitles;
- visual layout;
- audio and video processing;
- playback structure.

An OVML document describes **what the project is and what should
happen during playback or rendering**.

It does not prescribe a particular playback engine, rendering
engine, operating system, programming language, media backend,
TTS provider, or user interface.

---

## 2. Scope

OVML can be used to describe a wide range of audiovisual projects,
including:

- lectures and lessons;
- presentations;
- courses;
- audiobooks;
- podcasts;
- Shorts, Reels and TikTok content;
- game voiceover and interactive dialogue;
- film and series voiceover;
- dubbing;
- anime and animated productions;
- other scripted audiovisual experiences.

The same OVML document may be interpreted by different
applications for different purposes.

For example:

- OpenVML Studio can use OVML as an authoring and production
  representation.
- OpenVML Player can use OVML as a playback description.
- A renderer can use OVML to produce a finished video.
- A packaging system can place OVML and its resources into an
  OVMZ container.
- AI-assisted authoring tools can use OVML as a structured
  representation of a creative work.

---

## 3. Design Principles

### 3.1 Declarative format

OVML describes the intended audiovisual experience rather than
implementing the rendering process itself.

An OVML document does not contain executable application code.

### 3.2 Separation of content and rendering

OVML describes content, structure, timing and creative intent.

The application interpreting OVML is responsible for deciding how
that description is rendered on a particular platform.

### 3.3 Core semantics

The semantics of an OVML document should remain independent of:

- operating system;
- browser;
- UI framework;
- audio library;
- video library;
- TTS engine;
- AI provider;
- cloud provider;
- programming language.

### 3.4 Human-readable format

OVML uses XML so that documents can be:

- read by humans;
- generated by software;
- modified by editors;
- validated automatically;
- processed by standard XML tooling.

### 3.5 Extensibility

The standard is designed to allow future extensions without
requiring the core format to become tied to a particular
application.

## 4. Document Model

An OVML document consists of four primary areas:

```
<ovml>
    <meta>
        ...
    </meta>

    <cast>
        ...
    </cast>

    <assets>
        ...
    </assets>

    <world>
        ...
    </world>

    <script>
        ...
    </script>
</ovml>

These areas have different responsibilities.

Element	Purpose
<ovml>	Root document
<meta>	Project metadata and presentation preferences
<cast>	Characters and voice configuration
<assets>	Media resource definitions
<world>	World canon — canonical entities of the project (locations, chronology, terms, etc.)
<script>	Narrative and audiovisual timeline
5. Root Element — <ovml>

The root element identifies an OVML document.

Example:

<ovml version="2.2" lang="en">
    ...
</ovml>
Attributes
Attribute	Type	Required	Description
version	string	yes	OVML specification version
lang	language tag	no	Default language of the document

Example:

<ovml version="2.2" lang="ru">

The lang attribute uses language identifiers such as:

ru
uk
en
de
fr
ru-RU
en-US

The language of individual elements may be more specific where
required by an implementation.

6. Metadata — <meta>

The <meta> element contains project-level metadata.

Example:

<meta>
    <title>Путешествие на Марс</title>
    <author>OpenVML Example</author>

    <preferences
        showSubtitles="true"
        subtitleFontSize="14"
        subtitleBg="rgba(0,0,0,0.7)"
        subtitleColor="#ffffff"
    />
</meta>
<title>

Human-readable project title.

<author>

Human-readable author or creator name.

<preferences>

Optional playback and presentation preferences.

Attribute	Type	Default	Description
showSubtitles	boolean	true	Display subtitles
subtitleFontSize	integer	14	Subtitle font size in pixels
subtitleBg	string	rgba(0,0,0,0.7)	Subtitle background
subtitleColor	string	#ffffff	Subtitle text color
7. Cast — <cast>

The <cast> element defines the characters used by the project.

<cast>
    <character
        id="narrator"
        name="Narrator"
        gender="neutral"
        age="adult"
        role="narrator"
    />

    <character
        id="alex"
        name="Alex"
        gender="male"
        age="adult"
        role="protagonist"
    />
</cast>

A character is referenced from script content by its id.

8. Character — <character>
Required attributes
Attribute	Type	Description
id	string	Unique character identifier
name	string	Display name
Optional attributes
Attribute	Type	Default	Description
color	HEX	#888888	Character UI color
gender	enum	neutral	male, female, neutral
age	enum	adult	child, teen, adult, elderly
role	enum	minor	protagonist, antagonist, major, minor, narrator
9. Voice Configuration

A character may contain voice configuration describing how dialogue
should be voiced.

<character
    id="alex"
    name="Alex"
    voiceId="ru-RU-DmitryNeural"
    voiceName="Dmitry"
    voiceLang="ru-RU"
    voiceEngine="edge-tts"
    pitch="1.0"
    rate="1.0"
/>

Voice configuration identifies the intended voice. The actual TTS
implementation is determined by the environment interpreting the
OVML document.

Voice attributes
Attribute	Type	Default	Description
voiceId	string	""	Provider-specific voice identifier
voiceName	string	""	Human-readable voice name
voiceLang	string	""	Voice language
voiceEngine	string	implementation-defined	TTS provider/engine identifier
pitch	float	1.0	Voice pitch
rate	float	1.0	Speech rate

Implementations may support additional voice parameters.

10. Media Processing Presets

A character may reference processing presets for audio, video or
images.

<character
    id="alex"
    name="Alex"
    audioProcessorFile="presets/audio/WarmVoice.ovml"
    videoProcessorFile="presets/video/Cinematic.ovml"
    imageProcessorFile="presets/image/WarmColors.ovml"
/>

The referenced files are standalone XML documents describing
processing parameters.

The OVML standard does not require a particular processing engine.

11. Assets — <assets>

The <assets> section describes media resources used by the project.

An asset may represent:

audio;
video;
image;
subtitle;
other media supported by an implementation.

The exact storage mechanism is implementation-dependent.

When OVML is packaged as OVMZ, assets may be stored inside the
container.

12. Script — <script>

The <script> contains the actual audiovisual structure of the
project.

It may contain:

chapters;
scenes;
text blocks;
dialogue;
audio;
video;
images;
breaks;
camera direction.

The script is declarative. It does not contain executable code.

13. Scenes — <scene>

A <scene> groups content belonging to a common dramatic or visual
context.

Example:

<scene
    color="#1a1a2e"
    atmosphere="тёплый закат, тишина, умиротворение">

    ...

</scene>
Attributes
Attribute	Type	Description
color	HEX color	Scene color used as a visual/UI hint
atmosphere	string	Description of the scene atmosphere

The color and atmosphere attributes describe creative intent.

They may be used by:

authoring tools;
AI assistants;
asset selection systems;
visual processors;
rendering systems;
plugins.

They do not require a specific rendering behavior.

13.1 Canon References — generic mechanism

A scene may reference a canonical entity from the project's world
canon via a child element with a ref attribute.

Any section in the world canon may be referenced the same way:

<scene>
    <location ref="rusty_anchor">
        <variation>
            <weather>rainy</weather>
        </variation>
    </location>

    ...
</scene>

The ref value is the id of an entity declared in the corresponding
section of the project-level <world> canon.

The mechanism is identical for every section. For example, a lecture
may reference a term:

<scene>
    <term ref="photosynthesis" />
    ...
</scene>

13.2 World Canon — <world>

The document-level <world> element describes the canonical entities of
the project's world.

It is declared once at the top of the document and acts as the single
source of truth across all scenes and chapters.

The world canon does not prescribe a fixed set of sections. A document
may declare the sections that its content requires.

Example — a story-geared canon:

<world>
    <locations>
        <location
            id="rusty_anchor"
            name="The Rusty Anchor"
            type="tavern">

            <era>fantasy-medieval</era>
            <style>rough-hewn oak, candlelight</style>
            <palette>hearth:#4a2f1a; walls:#3a2a1e</palette>
            <props>cracked bar, long benches, hearth</props>
            <atmosphere>low murmur, smell of ale and smoke</atmosphere>
        </location>
    </locations>

    <timeline>
        <era id="war_of_ashes" name="War of Ashes">
            <from>1240</from>
            <to>1265</to>
            <summary>...</summary>
        </era>
    </timeline>
</world>

Example — a knowledge-geared canon (lecture, documentation):

<world>
    <terms>
        <term id="photosynthesis" name="Photosynthesis">
            <definition>The process by which light is converted into chemical energy.</definition>
            <section>Biology, chapter 3</section>
        </term>
    </terms>
</world>

Every section follows the same structural rule:

a section is a container of named entities;
an entity has a stable id and a display name;
an entity may contain arbitrary clarifying child elements;
an entity is referenced from script content by ref.

The world canon holds the permanent properties of its entities.
Context-specific change (time of day, weather, temporary props) is
expressed by the referencing scene's <variation> rather than by
editing the canon.

The <world> element is optional.

A document without a world canon is valid.

14. Camera Direction — <camera>

The <camera> element describes intended camera composition and
movement.

It is a directorial description, not a command to a specific
camera engine.

Example:

<camera
    shot="medium"
    position="center"
    movement="static"
    focus="alex"
/>

The exact <camera> vocabulary is defined by the Camera Direction
section of this specification.

15. Text Blocks

Text content is represented using <p> and <line>.

Example:

<p>
    <line char="alex">
        Привет!
    </line>
</p>

A paragraph may contain one or more lines.

16. Dialogue Line — <line>

The <line> element represents a unit of spoken or displayed text.

Example:

<line
    char="alex"
    startMode="afterPrevious"
    startDelay="0"
    wordByWord="true"
    wordByWordMode="single"
    wordDisplayDuration="100">
    Текст реплики
</line>
Timing attributes
Attribute	Type	Description
startMode	enum	Timing mode
startTime	float	Start time in seconds
startDelay	float	Additional delay
char	string	Character identifier
Display attributes
Attribute	Type	Description
marquee	boolean	Enable marquee text
wordByWord	boolean	Enable word-by-word display
wordByWordMode	enum	single or cumulative
wordDisplayDuration	integer	Word display duration in milliseconds

Additional typography and grid attributes may be applied.

17. Word-by-Word Text

OVML can explicitly group words for synchronized display.

<line
    wordByWord="true"
    wordByWordMode="cumulative"
    wordDisplayDuration="500">

    <w group="1">Привет</w>
    <w group="1">мир</w>
    <w group="2">как</w>
    <w group="2">дела</w>

</line>

The exact visual representation is determined by the player.

18. Media Blocks

OVML supports media blocks such as:

<video ... />
<img ... />
<audio ... />

Example:

<video
    src="asset_id"
    layer="background"
    volume="1"
    duration="10"
    startTime="0"
    startMode="absolute"
    startDelay="0"
    loop="false"
    gridRow="1"
    gridCol="1"
    gridRowSpan="1"
    gridColSpan="1"
    sizePercent="100"
/>
19. Timing Model

OVML provides explicit timing relationships between blocks.

The primary modes are:

Mode	Meaning
afterPrevious	Starts after the previous textual block
duringCurrent	Starts relative to the current timeline context
absolute	Starts at an absolute timeline position

For media blocks, the default startMode is:

absolute
20. Break

A pause may be explicitly inserted into the script.

<break time="1000" />

The value is expressed in milliseconds.

21. Layout

Text and media elements may use a grid-based layout.

gridRow="1"
gridCol="1"
gridRowSpan="1"
gridColSpan="1"

Media elements may additionally specify:

sizePercent="100"

The exact visual implementation is platform-dependent.

22. OVMZ

OVMZ is the packaged form of an OVML project.

A typical OVMZ package contains:

project.ovmz/
├── content.ovml
├── project.json
├── resources/
│   ├── audio/
│   ├── video/
│   └── images/
├── presets/
│   ├── audio/
│   ├── video/
│   └── image/
└── tts/

OVMZ packages the project and its resources for distribution or
offline playback.

23. OVMV

OVMV represents a rendered audiovisual result of an OVML project.

Unlike OVMZ, which preserves the structured project, OVMV contains
the rendered media result.

A renderer may use OVML timing, scenes, camera direction, assets,
voice configuration and processing instructions to produce the
final media.

24. Validation

An OVML document must be structurally valid XML and conform to the
rules defined by this specification.

Validation includes:

XML structure;
required elements;
required attributes;
supported attribute values;
references to known characters;
valid timing values;
valid media references where applicable.

An OVML parser is responsible for rejecting malformed documents.

The player is responsible for interpreting a valid document.

25. Extensibility

OVML may be extended by future versions of the standard and by
implementation-specific mechanisms.

Extensions must not change the meaning of existing standard
elements in a way that makes valid OVML documents ambiguous.

Implementations may ignore extensions they do not understand,
provided that doing so does not make the document unsafe or
structurally invalid.

26. Version

This document defines OVML 2.2.

The version is declared in the root element:

<ovml version="2.2">

An implementation may reject documents using a version it does not
support.

28. Summary

OVML is a declarative representation of an audiovisual project.

It describes:

what the project contains;
who participates;
what is said;
which media are used;
when events occur;
how scenes are conceptually composed;
what camera direction is intended.

The application interpreting OVML determines how these
intentions are realized on a particular platform.
